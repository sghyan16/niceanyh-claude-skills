# Argument Architecture Skill

将零散观点转化为具有传播力内容的完整工作流。

---

## 核心理念

一个观点能传播，需要三件事：
1. **前置**（Setup）：为什么听众要在意这个问题
2. **核心**（Core Claim）：你真正想说的那一句话
3. **后置**（Payoff）：接受这个观点之后，世界观/行动如何改变

用户通常有 Core Claim，缺的是 Setup 和 Payoff，以及三者之间的**因果链**（不是并列关系）。

---

## 工作流步骤

### Step 1：提取与诊断

接收用户输入（可以是：碎片笔记、语音转录、粗糙草稿、bullet points）后，执行：

**A. 提炼核心观点**
- 找出用户真正想说的那一句话（往往藏在中间或结尾）
- 用一句话表达，不超过30字
- 识别这个观点挑战了什么常识/主流认知（认知张力）

**B. 诊断现有素材**
- 哪些素材是强证据（具体场景、数据、故事）
- 哪些是弱素材（泛泛而谈、重复论点）
- 素材之间是"并列"还是"递进"——并列是结构性问题

**C. 识别缺失环节**
- 前置钩子是否存在？听众为什么要在意？
- 论点之间有没有因果链？
- 结尾是否有"反弹回读者"的动作？

---

### Step 2：构建叙事架构

输出以下结构（用中文）：

```
【核心观点】
一句话：___

【认知张力】
这个观点挑战了：___
目标读者原来相信：___

【叙事架构】

① 开场钩子（制造冲突或共鸣）
   → 用什么场景/问题/反常现象让读者停下来？

② 前提建立（让读者接受你的视角）
   → 需要读者先承认什么，才能接受你的观点？
   → 用什么素材/故事建立这个前提？

③ 核心观点呈现
   → 如何让这句话有力量？（类比、数据、极端案例）

④ 深化/反驳（给观点加厚度）
   → 最强的反驳是什么？如何处理它？
   → 或：这个观点延伸出什么更深的洞察？

⑤ 反弹回读者（Payoff）
   → 读者接受这个观点后，对他们自己意味着什么？
   → 这一步是传播的关键——让读者感到"这说的是我"

【推荐叙事模式】
从以下中选择最适合的1-2种：
- 冲突型：A vs B，最终解构对立
- 反常识型：大家以为X，其实是Y
- 递进型：表面→本质→更深本质
- 个人叙事型：经历→洞察→普适原则
```

---

### Step 3：生成脚本草稿

基于上述架构，生成一份完整的内容脚本。

**字数与节奏：**
- 目标长度：300-500字（对应2-3分钟口播），宁少勿多
- 每句话必须承载具体信息量，删掉所有填充语（"其实"、"说实话"、"大家都知道"、"不得不说"）
- 段落最多3-4句，口语节奏，不写长句

**格式要求：**
- 开头：用具体场景或问题切入，不超过2句话
- 每个论点段落：场景/证据 → 观点 → 意义，不直接上结论
- 过渡句要显式写出（不能靠读者自己脑补逻辑跳跃）
- 结尾：把问题反弹回读者，制造坐立不安感或行动冲动

**知识感要求（个人品牌核心）：**
- 脚本中必须植入1-2个受众可以转述的"硬知识点"——具体概念、框架名称、反直觉数据，或一个有命名感的观察
- 结尾留"知识钩子"：让受众感到今天拿到了一个新的思维工具，而不只是听了一个故事
- 示例句式："我把这个现象叫做___"、"这背后有个___定律"、"这其实是个___问题"

**语言风格（个人品牌用词）：**
- 精准优先于华丽——用最小的词承载最大的信息量
- 犀利但不刻薄：点到矛盾本质，不做情绪化煽动
- 有认知高度感：用词体现视角独特，而非人云亦云
- 避免：口水词、大词空话、"共鸣式废话"（"很多人都有这种感觉"）

**极简延展（可选）：**
- 在核心观点站稳后，可向一个相邻议题延伸一步，增加话题厚度
- 延伸必须与核心观点有逻辑联系，不是强行扩展
- 最多1个延伸点，延伸段不超过50字

**脚本标注：**
在关键位置加注释，说明为什么这样写：
```
[钩子：用反常识开场，制造认知摩擦]
[硬知识点：命名这个现象，让受众有可转述的概念]
[过渡：因果链，不是转折]
[延展：从X延伸到Y，同一底层逻辑]
[Payoff：把问题反弹回读者，触发自我对照]
```

---

### Step 4：输出诊断报告（如果用户提供的是已有草稿）

如果用户输入的是一篇已有内容，额外输出：

```
【原稿诊断】
✓ 做得好的：___
✗ 结构问题：___
✗ 传播力弱点：___

【重构建议】
核心观点需要从___ 调整为 ___
开场需要改成：___
结尾需要加：___
```

---

## 使用提示

- 用户可以输入：碎片笔记、语音转录、已有草稿、bullet list，都能处理
- 如果用户只有1-2个观点，重点做 Step 2（架构）
- 如果用户有完整草稿，重点做 Step 4（诊断）+ Step 3（重写）
- 脚本长度默认300-500字（2-3分钟口播），超出则裁剪，不扩充
- 每次只聚焦一个核心观点——多观点并排是结构的敌人
- 知识感 > 共鸣感：让受众带走一个可转述的概念，比让他们感动更有传播价值
- 语言是人设的一部分：每次用词都在积累或损耗个人品牌，谨慎对待

## 常见叙事结构模板

### 模板A：反常识型（适合观点强、反直觉的内容）
```
[场景]大家都以为___
[转折]但我在___发现了一个让我困惑的现象
[建立前提]要理解这个，我们需要先接受___
[核心观点]所以真相是：___
[延伸]这意味着，___其实也是同样的逻辑
[反弹]那么对你来说，这意味着___
```

### 模板B：递进型（适合有深度洞察、层层剥开的内容）
```
[表象]我们看到的是___
[第一层]背后的原因是___
[第二层]但更深的原因是___
[本质]而本质是：___
[行动]所以下一步应该___
```

### 模板C：个人叙事型（适合有具体经历/观察的内容）
```
[经历]我在___的时候，看到/经历了___
[困惑]这让我开始想：为什么___？
[洞察]后来我意识到：___
[普适]这其实说明了一个更大的道理：___
[邀请]你有没有也___过？
```
